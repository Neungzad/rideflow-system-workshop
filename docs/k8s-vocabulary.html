🏗️ Cluster & Node

A Cluster is everything — all the machines and software that make up your Kubernetes environment. A Node is one machine (real or virtual) inside the cluster.

Cluster Structure

☸️ CLUSTER (Minikube on your Mac)
💻 NODE — minikube (your laptop VM)
kafka-broker
redis-master
rabbitmq
postgres-user
user-service
order-service
In production (EKS on AWS): the cluster has 3+ nodes spread across availability zones. Minikube = 1 node for local dev.
🌐 Cluster infra
The entire Kubernetes environment. Contains all nodes, pods, and resources. In RideFlow: one Minikube cluster locally, one EKS cluster on AWS.
💻 Node infra
One machine in the cluster. Runs pods. In Minikube you have 1 node. In production you'd have 3+ nodes for redundancy.
kubectl get nodes

📁 Namespace

A Namespace is a logical folder inside the cluster. It separates teams, projects, or environments so they don't interfere with each other.

We put all RideFlow resources in the rideflow namespace. This keeps them isolated from Kubernetes system pods. Always add -n rideflow to kubectl commands.

🫛 Pod

A Pod is the smallest deployable unit in Kubernetes. It wraps one (or more) containers and gives them a shared network and storage.

Pods are ephemeral — they can die. Deployments restart them automatically.

🫛 Pod app
One running instance of your app. Like a process. Has its own IP inside the cluster. Never create pods directly — use Deployments so K8s can restart them if they crash.

⚙️ Workloads — Deployment & StatefulSet

Workloads tell Kubernetes how to run your pods — how many replicas, how to update them, and how to restart them.

Deployment vs StatefulSet

Deployment — stateless
user-service-abc12
user-service-xyz99
Pods are identical & interchangeable.
Any pod can die — another starts.
StatefulSet — stateful
postgres-user-0
kafka-broker-0
Pods have stable names (-0, -1, -2).
Each keeps its own data volume.
🔁 Deployment app
For stateless services like user-service, order-service, api-gateway. Manages replicas, rolling updates, auto-restart. "Keep 2 copies of this pod running."
kubectl get deployments -n rideflow
📦 StatefulSet app
For stateful apps: Kafka, Redis, PostgreSQL, RabbitMQ. Pods get stable DNS names (pod-0, pod-1) and persistent storage.
kubectl get statefulsets -n rideflow

🔵 Service network
A stable DNS name + port pointing to a set of pods. Even if pods restart and get new IPs, the Service address never changes. Types: ClusterIP (internal), NodePort (dev), LoadBalancer (cloud).
# Internal DNS format:
service-name.namespace.svc.cluster.local

# e.g. Kafka broker:
rideflow-kafka-kafka-bootstrap.rideflow.svc.cluster.local:9092
🚪 Ingress network
The external front door. Routes HTTP/HTTPS traffic from outside the cluster to internal Services based on hostname or URL path. We use Nginx Ingress in RideFlow.
rideflow.local/api/users → user-service:8001
rideflow.local/api/orders → order-service:8002
rideflow.local/api/menu → merchant-service:8003

⚙️ ConfigMap & Secret

Store configuration outside your container image so you can change settings without rebuilding.

How pods read config

ConfigMap
rideflow-config
→
Pod (user-service)
env: KAFKA_BROKERS=...
←
Secret
user-secrets
📋 ConfigMap config
Non-sensitive key-value pairs injected as environment variables. Our rideflow-config stores Kafka broker address, Redis host, environment name.
kafka_brokers: "rideflow-kafka-...:9092"
redis_host: "redis-master.rideflow..."
environment: "development"
🔐 Secret config
Sensitive data: passwords, API keys, JWT secrets. Base64-encoded in K8s. Never hardcode secrets in code or YAML — always reference from a Secret.
# user-secrets contains:
db_password: "..."
jwt_secret: "..."

💾 Storage — PV & PVC

Pods are ephemeral — when they restart, their disk is wiped. PersistentVolumes survive pod restarts.

💿 PersistentVolume (PV) storage
A piece of storage provisioned by the admin (or auto-provisioned). Like a hard drive available in the cluster.
📎 PersistentVolumeClaim (PVC) storage
A request for storage by a pod. "I need 5GB of disk." K8s matches the PVC to a PV. StatefulSets create PVCs automatically per replica.
In this workshop: we use storage.type: ephemeral for Kafka and persistence.enabled: false for PostgreSQL. This means data is lost on restart — fine for local dev, never for production.

🧩 CRD — Custom Resource Definition

Kubernetes ships with built-in types: Pod, Deployment, Service. A CRD lets you add new custom types. Strimzi adds Kafka and KafkaTopic so you can manage Kafka like a native K8s resource.

Built-in vs Custom resources

Built-in K8s types
kind: Pod
kind: Deployment
kind: Service
kind: ConfigMap
Strimzi CRDs (custom)
kind: Kafka
kind: KafkaTopic
kind: KafkaNodePool
🧩 CRD + Operator pattern infra
CRD = teaching K8s a new vocabulary word. Operator = the brain that acts on it. You write kind: Kafka, the Strimzi Operator reads it and provisions brokers, ZooKeeper (or KRaft), topics, users — all automatically.
kubectl get kafka -n rideflow
kubectl get kafkatopics -n rideflow
kubectl get crd | grep strimzi
